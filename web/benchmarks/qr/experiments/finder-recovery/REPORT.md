# v3.15：模块中心采样与结构灰度校准

本轮继续处理v3.14精细模式剩余的11处失败位置。新增两处有效解码，均在blurred/image005.jpg；两次完整95张回归均为114/123，曲面组保持60/60。没有换解码器、添加模型、修改图片/标注、上传图片、推送或部署。

## 原因与处理

此前局部几何模型用滑动窗口的最小/最大灰度归一化，再在每个模块内取9点平均。它能处理光照变化，但在模糊区域，局部极值与邻近模块混色可能改变黑白判定。本轮尝试另一条补充路径：保留原灰度，取模块中心，用三个定位方块和时序线的已知黑白位置估计亮度范围，再由普通ZXing验证阈值化结果。

已知图案只用于估计黑白均值，不把期望的定位方块、时序位或任何内容写回采样矩阵。数据区仍全部来自照片。没有用人工四角、已知内容或其他副本的解码结果选择模型。两处成功的内容哈希虽已出现在其他图片中，但不是输入先验。

研究先尝试了441种小相位/尺度组合，并按功能图案匹配度排序，在image005的两个区域找到新增。随后消融发现：不必保留这个搜索；零相位、零尺度修改、中心采样、少量阈值已能成功，普通与isPure均可。产品没有加入相位遍历，也没有切换到isPure。

## 同几何与阈值的消融

`calibration-ablation.mjs`固定两种实际裁剪策略、384/448工作边、相同几何模型与四个阈值，比较：原有9点局部极值采样、局部极值中心采样、原灰度中心采样、结构校准中心采样。表中为成功的参数版本数，不是不同二维码数量。

| 输入 | 原9点局部极值 | 局部极值中心 | 原灰度中心 | 结构校准中心 |
| --- | ---: | ---: | ---: | ---: |
| image005候选2，模块留边，384 | 0 | 0 | 1 | 3 |
| 同区域，模块留边，448 | 0 | 1 | 3 | 11 |
| 同区域，百分比留边，384 | 0 | 0 | 0 | 0 |
| 同区域，百分比留边，448 | 0 | 0 | 2 | 7 |
| image005候选3，384 | 0 | 0 | 1 | 3 |
| 同区域，448 | 0 | 0 | 0 | 0 |

中心采样本身在部分模型上已有收益，不能说只有结构校准才可能成功。结构校准在本组参数中使更多版本可解码。448也没有普遍优于384：候选3只在384成功，因此保留384优先。

## 裁剪留边的运行波动

实测接入第一轮只补出候选3。原因是原有`cropRegion`的150ms定位尺度探测有时未及时找到结构，退回20%留边：候选2从`left=1431,top=2130,width=670,height=596`变成`1425,2139,682,577`。两种输入缩到384后，几何拟合与采样略有不同；后者在384下没有新增。

这不是使用旧缓存裁剪就能视为完成的实现。本轮专门对这两种实际留边做对照，确认448能覆盖百分比留边的情况。因此产品采用384优先、失败后448，不放大超过原区域、不重复相同实际尺寸。没有用固定文件名或固定裁剪坐标写入产品。

首轮完整产品测试中候选2通过448、第51次结构解码成功；确认轮在模块留边下通过384、第8次成功。候选3两轮均在384、第3次成功。全量及实际浏览器均保留两处新增。

## 受限产品实现

新模块为`js/structure-sampling.js`和`structure-decoder.js`，只随原有“精细模糊恢复”开启，默认关闭，与TPS独立。

1. 原整图、WeChat候选、局部增强、曲面处理及分级恢复先按原顺序执行。
2. 对最多3个未解决原区域，以384、失败后448工作边重新拟合，最多12个模型/级，几何预算600ms/级。
3. 从三个7×7定位图案与时序线的黑白中心估计均值；所有组需正向亮度分离且差值大于8，坐标必须有限、在图内。分数仅作诊断，不是置信度。
4. 用`(原灰度−黑均值)/(白均值−黑均值)`校准模块中心灰度，尝试0.5/0.6/0.7/0.75四个阈值，普通ZXing实际解码成功才返回。重复几何模型不因旧阈值不同重复处理。
5. 每区域最多96次解码、2500ms，整图7500ms，采样1000ms/级。预算在任务之间检查，无法中断一次几何/解码调用；未完成预算、有限尝试失败和运行异常分别记录。
6. 成功覆盖区域即停止其后续处理，继续其他候选；失败给原恢复后校正保留完整预算，新增步骤异常也不阻止旧补试。新阶段不占用原恢复和旧恢复后校正的时间预算。

该路径使用原区域，不依赖先生成17张恢复图。灰度与模型缓冲不跨区域缓存，工作Canvas用完归还为1×1。原图、导出裁图、其他功能与现有空间去重不变。

## 没有进入产品的实验

- **灰度范围展开**：按ROI的p2/p98、p10/p90拉伸后尝试既有恢复与几何，11区域无新增。部分暗图产生了更多模型，但模型数增加并非识别增益。`tone-run.mjs`与`local-finder-tone.jsonl`保留记录。
- **不依赖闭合环的新finder扫描**：行列1:1:3:1:1比例扫描、交叉复核、灰度7×7模板；两个强点时仅在有像素证据的受限位置搜索第三点。6个原无模型区域均得到三点候选，目视与结构检查支持其位置；它们不是人工真值认证。模板四角标注`gray-template-fitted`，不可当作实测轮廓。15点透视、8邻近版本、灰度/二值及普通/pure共504次，没有新增，不接入产品。
- **相位/尺度遍历**：仅作为发现机制的实验，最终不需要。其余有模型区域的有限尝试未新增；达到1200次上限的轮次标记预算跳过，不能说已穷尽。

新扫描在384工作边约140～284ms、600边约390～501ms；完美三定位合成控制、白图拒绝、预算为零与非法输入检查通过。算法思路参考[ZXing FinderPatternFinder](https://github.com/zxing/zxing/blob/master/core/src/main/java/com/google/zxing/qrcode/detector/FinderPatternFinder.java)，本轮为独立实现，没有移植其整套定位器。后续仍可研究模糊PSF、亚像素模板边界和更准确的网格拟合；当前不将“扫描点看起来正确”当作足够接入依据。

剩余9个位置来自image019两处、020三处、021一处、036、037、045。本轮结果不能证明它们不可恢复。

## 统计、验证与复跑

CSV保留全部旧列与人工补记字段，在末尾追加结构校准区域数、次数、准备/拟合/采样/解码耗时与预算跳过数。JSON保留每级工作尺寸、几何原因、尝试的黑白均值与选定阈值，版本为`3.15-structure-gray`，schema仍为2。`structure_total`是父阶段，不与子阶段相加。原“全部识别”仍只指已发现候选覆盖，未知漏检由人工补记。

实际Chromium通过13张精细回归，image005返回3个，并确认两个区域由结构校准解码。TPS+精细组合检查image005/019/021、curved017分别返回3/1/2/2。界面检查通过选项持久化、设置迁移、统计/ZIP下载、刷新恢复、二维码遮盖、五标签页和EAN13识别。30项自动检查通过，包含新校准仿射亮度不变性、数据区不被写成已知图案、输入不修改、预算/运行异常区分、小图不放大或重复、CSV列与父子耗时。
