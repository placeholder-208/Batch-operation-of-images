# 心裁

浏览器图片工作台：二维码识别与裁切、二维码遮盖、条形码识别、语义裁剪和本地分割。二维码、条形码和分割在本机运行；语义裁剪与可选的网页信息查询通过 Worker API 联网。

## 目录

```text
web/
├── index.html              页面入口
├── js/                     应用逻辑、图像处理及各功能界面
│   └── segmentation/       本地分割、提示与蒙版编辑
├── assets/                 品牌图片与当前样式
├── models/                 WeChat 检测与 SlimSAM 模型
├── vendor/                 ORT WASM、分割运行库、PDF.js 及许可
├── zxing/                  ZXing 加载脚本和 reader WASM
├── server/                 Worker API 实现
├── worker.js               Cloudflare Worker 入口
├── wrangler.jsonc          部署配置
├── test/QRcode/            用户测试图片与四角标注
└── benchmarks/             本地评估、结果与历史归档
    ├── qr/                 QR 评估程序；archive/v3.9 保存旧更新材料
    ├── segmentation/       分割模型评估，独立于产品
    └── archive/            编辑器恢复文件与旧样式，不提交、不部署
```

## QR 正式流程（v3.12）

每图一次基础 ZXing 解码 → WeChat 补充候选 → 对未覆盖候选依次进行原区域解码和四种局部增强 → 对剩余失败区域进行柱面校正 → 原模块二值采样仍失败时，补充连续灰度采样 → 对仍未解决的局部区域补做受限去模糊恢复。

去模糊采用有限组高斯/直线运动模糊假设的 Wiener 恢复，再交由 ZXing 验证。默认先在384像素工作边尝试17种滤波，失败后在448像素补试5种高斯核；“精细模糊恢复”默认关闭，开启后再以576像素补试17种滤波。尺寸不超过原区域大小，相同实际尺寸不重复处理，核宽随工作分辨率同比调整。每图最多3个区域；默认区域1500ms/整图4500ms，精细模式3500ms/10500ms，均在任务间检查，不是严格中断期限。只处理原流程仍未解决的区域，不修改原图与导出裁图像素；恢复坐标映射回原图并参与正常去重。

区域一旦被成功结果覆盖就停止继续加工该区域，继续处理其他候选。保留原区域与几何预算。TPS 与精细模糊恢复均默认关闭，可在“识别选项”中独立打开。TPS失败后仍尝试柱面校正。旧的调整顺序开关已退役，旧工作状态中的该设置会忽略；识别选项和图片、结果、历史统计继续恢复。

统计 CSV 保留全部原列和人工补记字段，包括供历史轮次比较的“调整检测顺序”列；新轮次该列恒为“是”。JSON 记录 `pipeline: region-first`、版本、各阶段及采样方式。统计中的“全部识别”仅代表已发现的候选全部覆盖，未知漏检仍需人工补记。

## 本地检查与部署

从本目录运行 Wrangler 开发服务器可同时测试静态页面与 Worker API。普通 `python -m http.server` 仅用于静态预览，不能处理 `/api/*` 请求。部署配置继续使用本目录作为 Cloudflare 静态资源根目录。

`.assetsignore` 排除测试数据、评估工具、开发配置与文档；不要删除模型、WASM、PDF.js 字库或供应商许可证。部署、推送和提交由开发者自行执行。

QR 评估与当前测试说明见 [benchmarks/qr/README.md](benchmarks/qr/README.md)。分割模型评估见 [benchmarks/segmentation/README.md](benchmarks/segmentation/README.md)。
